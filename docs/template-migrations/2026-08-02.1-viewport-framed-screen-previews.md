# Screen previews are viewport-framed; feature modules render SHRINK

A screen's golden should read as a screenshot of the app on a device, not a render on the snapshot
harness's canvas. The harness canvas is a deliberately oversized 960 dp square whose only job is to
never be the constraint — but under the old feature-module default (`RenderingMode.NORMAL`, which
always emits the full canvas) it framed every golden anyway: a `fillMaxSize` screen preview was
stretched over the square, and anything smaller was padded out with dead canvas that dilutes the
pixel diff and hides real change in review.

Two pieces fix that together, and only together — guidance alone cannot trim a PNG:

- **`UkptPreviewFrame`** (new, in the design module's `commonMain`): the viewport-sized root a
  screen `@Preview` wraps its content in. It fixes the render at the project's primary form factor
  (`UkptViewport.Default`'s width, 844 dp tall by default), pins the palette, and measures the
  viewport from its own bounds.
- **Feature-module `PreviewSnapshotTest` passes `RenderingMode.SHRINK`**, which crops each golden
  to the preview's own bounds — a framed preview's golden is exactly the frame. `SHRINK` keeps
  device-bounded constraints, so a root-`verticalScroll` preview still renders (the blank-render
  hazard is `V_SCROLL`'s unbounded height, not `SHRINK`), and an unframed `fillMaxSize` preview
  still renders the full square canvas **byte-identical** to the old default — both verified in the
  template. Flipping the mode before converting previews is therefore safe.

The design module's doc surfaces already work exactly this way (`DocSurface` + SHRINK, per the
2026-08-02 migration); this extends the same principle — the viewport is the frame, the canvas is
only a ceiling — to screen snapshots.

## Detection

A project is affected if a feature client module's `PreviewSnapshotTest` does not override
`renderingMode`:

```bash
grep -rln "PreviewSnapshotTestCase(case)" feature/*/client/src/androidHostTest
```

or if screen goldens are full-canvas squares (1000 x 1000 px) rather than viewport-shaped. Projects
that already frame previews and render SHRINK are done.

## Migration

1. Copy `UkptPreviewFrame.kt` from the template's
   `platform/client/design/src/commonMain/kotlin/platform/design/` into the project's design
   module, renaming `Ukpt` to the project's type prefix. Set the default `width`/`height` to the
   project's primary form factor (they should describe the same device as `<Prefix>Viewport.Default`).
   A project with its own theme shape adapts the frame's body — the point is a fixed viewport-sized
   root that applies the theme with a pinned palette.
2. In each feature client module's `PreviewSnapshotTest`, pass
   `renderingMode = RenderingMode.SHRINK` (import
   `com.android.ide.common.rendering.api.SessionParams.RenderingMode`). This alone changes no
   goldens.
3. Wrap each screen preview's content in `<Prefix>PreviewFrame(colors = …)`, replacing any bare
   theme wrapper the preview used to pin its palette. Previews that are deliberately not screens
   (component previews) may stay unframed, but consider bounding them too — dead canvas is noise.
4. Re-record and review, per client module:
   ```
   ./gradlew :feature:<name>:client:recordPaparazzi --no-configuration-cache
   ./gradlew :feature:<name>:client:verifyPaparazzi --no-configuration-cache
   ```
   Framed goldens become viewport-sized (the template's 390 x 844 dp frame emits 462 x 1000 px
   after Paparazzi's downscale). Look at them — they should read as device screenshots.

## Verification

`verifyPaparazzi` is green per client module; screen goldens are frame-shaped rather than
1000 x 1000 squares; `grep -rln "PreviewSnapshotTestCase(case)"` under `feature/*/client` finds
nothing.
