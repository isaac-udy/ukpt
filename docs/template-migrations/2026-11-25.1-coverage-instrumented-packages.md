# Include project-specific packages in Kover instrumentation

During coverage runs, Kover instruments classes under `feature`, `platform`, `app`
and the package named by `ukpt.projectNamespace`. Each root includes its subpackages.

## Detection

Before the first coverage run after updating, compare the package declarations in the
production sources of the reported modules with these four roots. For example, list the
Kotlin packages under the template's module directories with the following command.

```sh
rg --no-filename '^package ' app feature platform -g '*.kt' -g '!**/architecture/**' \
  -g '!**/tests/src/**' -g '!**/src/*Test/**' -g '!**/src/test/**' | sort -u
```

Only production declarations in reported modules need an entry. Test sources and packages
excluded from the coverage report can be skipped.

## Migration

Add any additional project-owned package roots to the existing `testCoverage` block in
the root `build.gradle.kts`. Each pattern includes the named package and its subpackages.

```kotlin
testCoverage {
    instrumentedPackages("ukpt.tools.*")
}
```

## Verification

Run `./gradlew testCoverageReport`. If the report names a missing package, add its root and
rerun the same command to collect coverage with the updated instrumentation.
