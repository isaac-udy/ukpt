# Compose modules enable Android resource processing by convention

The `ukpt.compose-library` convention plugin now sets `androidResources { enable = true }` on every
Compose module. AGP 9's KMP library plugin disables Android resource and asset processing by
default, and Compose Multiplatform ships a module's `composeResources` (strings compiled to `.cvr`,
fonts, drawables) as Android **assets**. With processing disabled the module publishes no assets
artifact, so the consuming APK never receives the pack.

The failure is nasty in two ways: fonts fail **silently** (the UI renders a fallback typeface),
while strings throw `MissingResourceException` at runtime. Host-JVM tests cannot catch either —
Paparazzi and unit tests read Compose resources from the classpath, not from APK assets — and stale
merged assets in `build/intermediates/assets` mask it until a clean build.

The same flag generates the R class Paparazzi resolves reflectively, so it also replaces the
per-module opt-in that Compose modules previously needed for host tests.

## Detection

A project is affected if any module enables this itself rather than inheriting it:

```bash
grep -rn "enableAndroidResources\|androidResources" --include="*.gradle.kts" .
```

Matches inside a module's own `build.gradle.kts` are now redundant. Either spelling counts — the
older `experimentalProperties["android.experimental.kmp.enableAndroidResources"] = true` and the
current `androidResources { enable = true }` do the same thing.

## Migration

1. Sync `build-logic/` from the template so `ukpt.compose-library` carries the flag. `build-logic`
   is template-owned, so the file sync covers it.
2. Delete the now-redundant per-module opt-ins found above from every module that applies
   `ukpt.compose-library`. Leave them in place for any module that does **not** apply that
   convention — it will not inherit the flag.

## Verification

Stale outputs hide this bug, so verify from clean:

```bash
./gradlew clean
./gradlew :app:client:android:assembleDebug --max-workers=2
unzip -l app/client/android/build/outputs/apk/debug/*.apk | grep composeResources
```

Expect one `assets/composeResources/<res-class-package>/…` entry per Compose module that has a
`composeResources` directory. Before the change only modules with a manual opt-in appear; after it,
all of them do.

Then confirm host tests still resolve their R class — a Compose module without the flag dies with
`ClassNotFoundException: <module>.R`:

```bash
./gradlew :feature:core:client:verifyPaparazzi --no-configuration-cache --max-workers=2
```
