# Snapshot harness moved to dev.isaacudy.udytils:snapshot

The Paparazzi harness that every client module used to copy — `SnapshotRule`,
`DirectorySnapshotHandler`, its test, and the `PreviewSnapshotTest` scaffold — now ships as the
`dev.isaacudy.udytils:snapshot` artifact. The copies had already drifted between projects (differing
`RenderingMode`s, and device configs whose names and stated intent disagreed while the values were
identical), which is precisely the problem a library solves.

A module now writes only the fact that is genuinely its own: the package tree to scan.

`UiLayer.Composable.previewsAreSnapshotTested` detects the harness by looking for
`PreviewSnapshotTestCase` in `src/androidHostTest/`, where it previously looked for
`AndroidComposablePreviewScanner`. **A project that has not migrated will fail that rule**, because
the scanner class is now an implementation detail of the library and no longer appears in consumer
code.

## Detection

A project is affected if it still carries its own copies:

```bash
find . -path "*/src/androidHostTest/*" \
  \( -name "SnapshotRule.kt" -o -name "DirectorySnapshotHandler.kt" -o -name "PreviewSnapshotTest.kt" \) \
  -not -path "*/build/*"
```

Any `PreviewSnapshotTest.kt` that references `AndroidComposablePreviewScanner` directly, rather than
extending `PreviewSnapshotTestCase`, needs migrating.

## Migration

1. Add the substitution alongside the other udytils modules in `settings.gradle.kts`:
   `substitute(module("dev.isaacudy.udytils:snapshot")).using(project(":snapshot"))`, and a
   versionless `udytils-snapshot = { module = "dev.isaacudy.udytils:snapshot" }` entry in
   `gradle/libs.versions.toml`. Projects consuming udytils from Maven rather than the submodule take
   a published version instead.
2. In each client module's `androidHostTest` dependencies, replace the ComposablePreviewScanner
   dependency with `implementation(libs.udytils.snapshot)`. The scanner and JUnit 4 come with it;
   Paparazzi itself still comes from the Paparazzi Gradle plugin.
3. Delete the local `SnapshotRule.kt`, `DirectorySnapshotHandler.kt` and its test.
4. Reduce each `PreviewSnapshotTest` to the scanned tree, substituting your own package root:

```kotlin
class PreviewSnapshotTest(
    case: PreviewSnapshotCase,
) : PreviewSnapshotTestCase(case) {
    companion object {
        @JvmStatic
        @Parameterized.Parameters(name = "{0}")
        fun cases(): List<PreviewSnapshotCase> = PreviewSnapshots.scan("feature.myfeature")
    }
}
```

`@RunWith(Parameterized::class)` is inherited from the base class; `@Parameterized.Parameters` must
stay on the concrete class because JUnit 4 insists on reading it there. Hand-written doc-surface
tests keep using `SnapshotRule` from the library, which retains stock flat golden names.

5. **Check your rendering modes before re-recording.** The library's defaults are `SHRINK` for
   `SnapshotRule.screen`/`component` and `V_SCROLL` for preview-driven cases. If a local copy used a
   different mode, the goldens for those surfaces will change. Re-record, then **review the diff
   visually** rather than accepting it — a changed mode can reveal content that was previously
   cropped.

## Verification

```bash
./gradlew :feature:core:client:verifyPaparazzi --no-configuration-cache --max-workers=2
./gradlew :platform:common:architecture:verifyArchitecture --max-workers=2
```

Goldens that were passing before the move should still pass **unchanged** where the rendering mode
did not change — the extraction is behaviour-preserving. `verifyArchitecture` confirms
`previewsAreSnapshotTested` now recognises the migrated tests.
