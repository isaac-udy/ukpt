# `exceptionNeedsReason` now rejects a blank reason

`ProjectRules.exceptionNeedsReason` is **tightened**. Its check previously required only one
non-quote character after `reason = "`, so a whitespace-only sign-off such as
`@ArchitectureException(ruleIds = ["…"], reason = " ")` satisfied the rule. The pattern now requires
a non-whitespace character inside the string, matching the rule's stated intent of a *non-blank*
reason.

The rule ID is unchanged, so existing `@ArchitectureException` annotations that already carry a real
reason are unaffected.

## Detection

The project is affected if any `@ArchitectureException` (on a declaration or a `@file:` annotation)
has a `reason` argument that is empty or only whitespace. `verifyArchitecture` reports each one after
the rule sync:

```
git grep -nE 'reason\s*=\s*"\s*"' -- '*.kt' '*.kts'
```

## Migration

For each reported annotation, replace the blank `reason` with a sentence that explains why the
exception exists and the intended resolution — the same non-blank explanation the rule has always
asked for. An exception that cannot be justified in a sentence should be removed and the underlying
issue fixed instead.

## Verification

`./gradlew :platform:common:architecture:verifyArchitecture` passes with no new exceptions, or with
exceptions the user has signed off.
