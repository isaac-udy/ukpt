# Desktop end-to-end tests and screen robots

End To End Tests now run. `:app:client:desktop`'s `src/test` hosts the app's root composable with
`runComposeUiTest`, against the server graph running in-process through the harness's new
`inProcessServer(server, edges) { … }`. `GreetingJourneyTest` is the worked example: it seeds a
greeting, clicks Greet, then confirms the reset dialog.

Compose UI Component Tests and End To End Tests drive screens through robots, one per screen. The
new `:platform:common:robots` holds `ScreenRobot`, `User` and `asUser { }`. A feature's robots live
in its `:tests` module's `src/main`, and find nodes by the `const val` tags in an
`object [Screen]Tags` beside the screen. A test has one `on[Screen] { }` block per screen visit,
with steps named for what the user does or sees (`clickGreetButton()`, `seeGreeting("Hi there")`).
Given the app's `RootContext`, `on[Screen]` also waits until the screen's destination is the active
one. `UkptScreenContentTest` (`:feature:core:client`, `src/jvmTest`) is the Compose UI Component
Test example.

`App()` is split: `AppContent()` holds the theme, the viewport and the root navigation container,
and `App()` wraps it in `KoinApplication`. Every shell still calls `App()`. `serverDependencies` in
`:app:server` is public, for the desktop test set.

`Scenario`'s client graph is now resolved when `client<T>()` is called. In `inProcessServer` that is
Koin's global context, which the app's `KoinApplication` starts.

The harness change, `:platform:common:robots`, the `compose-uiTest` catalog entry and the rules
arrive with the file sync. `App.kt`, `ServerDependencies.kt`, the desktop and feature build files,
the screens' tags, the robots and the tests are project code.

New Constructs: `ClientUi.ScreenTags`, `Testing.Robot`. New rules:
`Testing.EndToEndTest.drivesTheAppRoot`, `Testing.EndToEndTest.drivesThroughRobots`,
`Testing.ComponentTest.drivesThroughRobots`, `Testing.Robot.placement`, `Testing.Robot.oneScreen`,
`Testing.Robot.userActionNames`, `Testing.Robot.hasEntryPoint`. Changed rules:
`Testing.testFunctionsAssert` counts a robot's `see…` calls as assertions;
`ModuleRules.clientApiOnly` allows a `:client` module's test dependency on its own feature's
`:tests` module; `ModuleRules.testSupportOnlyFromTests` lists `:platform:common:robots`. No rule ID
is renamed or removed.

## Detection

```bash
# App.kt without AppContent (no output once migrated)
grep -rL 'fun AppContent' --include='App.kt' app/client/common/src/commonMain

# serverDependencies still internal
grep -rn 'internal fun serverDependencies' --include='*.kt' app/server

# Desktop test set
ls app/client/desktop/src/test 2>/dev/null

# Compose UI tests finding nodes directly (no output once migrated)
grep -rlE '\b(onNode\w*|onAllNodes\w*|onRoot|perform\w+)\s*\(' --include='*.kt' feature/*/client/src/jvmTest feature/*/client/src/desktopTest app/client/desktop/src/test 2>/dev/null
```

## Migration

1. In `App.kt`, move the body inside `KoinApplication { … }` into a public `@Composable fun
   AppContent()`, and call `AppContent()` from `App()`:
   ```kotlin
   @Composable
   fun App() {
       KoinApplication(application = { modules(clientDependencies) }) {
           AppContent()
       }
   }
   ```
2. Make `serverDependencies` in `app/server/.../ServerDependencies.kt` public.
3. Add `api(projects.platform.common.robots)` to each `:feature:<name>:tests` build file.
4. For each screen a Component Test or End To End Test drives:
   1. Add `object <Name>ScreenTags` in its `client.ui` package, copying `UkptScreenTags.kt`, and
      apply each tag with `Modifier.testTag(…)`: the screen's root and every node a test uses.
   2. Add `<Name>ScreenRobot.kt` to the feature's `:tests` module, `src/main`, copying
      `UkptScreenRobot.kt`: the `User.on<Name>Screen` entry point and one `click…`/`enter…`/`see…`
      function per step.
5. Move each Compose UI Component Test's node lookups into the robot, and wrap its steps in
   `asUser { on<Name>Screen { … } }`. The `:client` module's `jvmTest` needs
   `implementation(projects.feature.<name>.tests)` and `implementation(compose.desktop.currentOs)`.
6. Add the desktop test dependencies and test task bounds from the template's
   `app/client/desktop/build.gradle.kts`: `:platform:common:testing`, `:platform:common:subcutaneous`,
   `:app:server`, each feature `:tests` and `:api` module the tests seed through, `libs.compose.uiTest`,
   `libs.koin.compose`, `libs.kotlin.test`; `maxParallelForks = 1`, `maxHeapSize = "1g"`.
7. Copy `app/client/desktop/src/test/kotlin/com/isaacudy/ukpt/appRootContext.kt` into the project's
   app package.
8. Write one `@EndToEndTest` for the project's main journey, copying `GreetingJourneyTest.kt`: seed
   with `given { }`, render `AppContent()` under `LocalRootContext` and a `KoinApplication` loading
   `clientDependencies + clientEdges`, then drive it with `asUser(rootContext) { … }`.

## Verification

```bash
./gradlew :app:client:desktop:endToEndTest
./gradlew componentTest
./gradlew :platform:common:architecture:verifyArchitecture
./gradlew subcutaneousTest
```

`endToEndTest` runs the desktop test classes annotated `@EndToEndTest` and the JVM exits after them.
`verifyArchitecture` reports no `Testing.EndToEndTest.*`, `Testing.ComponentTest.*` or
`Testing.Robot.*` failures.
