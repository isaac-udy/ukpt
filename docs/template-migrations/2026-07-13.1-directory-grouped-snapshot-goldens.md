# Directory-grouped snapshot goldens

Preview snapshot goldens move from one long flat filename per preview to a directory-grouped layout
named after the preview's declaring package and function.

Before:
```
snapshots/images/platform.snapshot_PreviewSnapshotTest_snapshot[feature.ukpt.ui.UkptScreenKt_UkptScreenPreview]_feature.ukpt.ui.ukptscreenkt.ukptscreenpreview.png
```
After:
```
snapshots/images/feature/ukpt/ui/UkptScreenPreview.png
```

The preview id appeared **twice** in the old name — once from `@Parameterized.Parameters(name = "{0}")`
in the test method name, and again from `paparazzi.snapshot(name = AndroidPreviewScreenshotIdBuilder(preview).build())`.

## What changed

- **New `DirectorySnapshotHandler.kt`** (in each client module's
  `androidHostTest/kotlin/platform/snapshot/`) — a custom Paparazzi `SnapshotHandler`. This is the only
  way to change the path scheme: stock `HtmlReportWriter` (record) and `SnapshotVerifier` (verify) both
  build the golden path via `Snapshot.toFileName`, which joins with `_` and cannot emit directories.
  The handler mirrors stock semantics — same `OffByTwo` pixel diff, same `maxPercentDifference`
  threshold, same width/height tolerance — and on failure writes a delta and the actual render under
  `build/paparazzi/failures/`, with an `accept with: mv …` hint in the assertion.
- **`PreviewSnapshotTest.kt`** now resolves each preview to a `PreviewCase` carrying its golden path,
  passes that relative path through `paparazzi.snapshot(name = …)`, and wires the handler. It keeps
  `@Preview` qualifiers (`name`, `fontScale`, `uiMode`, `device`) via
  `AndroidPreviewScreenshotIdBuilder(preview).ignoreClassName()`, so several `@Preview`s stacked on one
  function stay distinct.
- **Collision guard** — two previews resolving to the same golden path now fail fast at
  test-parameter creation, naming the colliding `declaringClass#method` pairs, instead of silently
  overwriting one another's goldens.
- JUnit display names become `[<package>.<PreviewFunctionName>]`.

## Detection

The project is affected if `feature/*/client/src/androidHostTest/snapshots/images/` contains flat
`platform.snapshot_PreviewSnapshotTest_snapshot[…].png` filenames, or if
`androidHostTest/kotlin/platform/snapshot/` has no `DirectorySnapshotHandler.kt`.

## Migration

1. Copy `DirectorySnapshotHandler.kt` and `PreviewSnapshotTest.kt` from the template into **every**
   client module that has an `androidHostTest/kotlin/platform/snapshot/` directory. Keep each module's
   own `scanPackageTrees(…)` argument — that is the only intended per-module divergence.
2. `git rm` the module's old flat preview goldens. **Only the preview-driven ones**: goldens produced by
   a hand-written `SnapshotRule` test or a design-system pipeline are not affected and must be kept.
3. Re-record and verify (the flag is required — see the `2026-07-13.1-configuration-cache` entry):
   ```
   ./gradlew :feature:<name>:client:recordPaparazzi --no-configuration-cache
   ./gradlew :feature:<name>:client:verifyPaparazzi --no-configuration-cache
   ```
4. Review the re-recorded images. GitHub will show them as delete + add rather than renames — expected,
   and a one-time cost.

If step 3 reports a golden-path collision, two `@Preview` functions share a name within one package;
rename one.

## Verification

```
./gradlew :feature:core:client:verifyPaparazzi --no-configuration-cache
```

Green, with goldens under `snapshots/images/<package>/<dirs>/<PreviewFunctionName>.png`.

Because the verifier is now hand-written, confirm it can actually fail: corrupt a golden, re-run
`verifyPaparazzi`, and check it reports `Images differ (by N%, tolerance 1.0000%)` and writes the delta
and actual images under `build/paparazzi/failures/`. Then restore the golden and re-verify green. A
custom verifier that cannot fail is worse than long filenames.
