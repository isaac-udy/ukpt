# Paparazzi wiring moves into the ukpt.snapshot-testing convention

Snapshot-testing a Compose module used to need ~25 lines of build boilerplate copied into every
module: the Paparazzi plugin, a host-test component, and a 17-line `doFirst` block adding the
aggregated stub-R jar to the test runtime classpath. That last one is the kind of thing nobody
reconstructs from scratch — the KMP library plugin puts the stub-R jar on the *compile* classpath
only, so without it Paparazzi dies with `ClassNotFoundException` resolving R reflectively, and
moving it to `androidHostTestRuntimeOnly` instead creates a task cycle.

The new `ukpt.snapshot-testing` convention plugin owns all of it. It builds on
`ukpt.compose-library` the same way that builds on `ukpt.kmp-library`, so a module applies one
plugin rather than two.

What stays in the module is what is genuinely the module's own: its `androidHostTest` dependency on
the harness, and the `PreviewSnapshotTest` naming the package tree to scan.

## Detection

A project is affected if any module wires Paparazzi itself:

```bash
grep -rln "plugins.paparazzi\|generateAndroidHostTestStubRFile" --include="*.gradle.kts" .
```

Matches outside `build-logic/` are modules that should adopt the convention.

## Migration

1. Sync `build-logic/` and `gradle/libs.versions.toml` from the template. `build-logic` is
   template-owned; the catalog gains a `paparazzi-gradlePlugin` entry, which must be on the
   convention plugins' classpath for them to apply Paparazzi.
2. In each affected module's `build.gradle.kts`, replace the `ukpt.compose-library` plugin and the
   Paparazzi alias with the single new convention:

```kotlin
plugins {
    id("ukpt.snapshot-testing")
    // …the module's other plugins
}
```

3. Delete from the module: the `withHostTestBuilder { }.configure { }` block, and the entire
   `tasks.withType<Test>` block adding the stub-R jar. Both now come from the convention.
4. Keep the module's `androidHostTest` dependency on `dev.isaacudy.udytils:snapshot` and its
   `PreviewSnapshotTest`.

A module that uses Compose but does **not** snapshot-test keeps applying `ukpt.compose-library`
directly — do not switch it over, or it gains a host-test component it has no use for.

## Verification

```bash
./gradlew :feature:core:client:verifyPaparazzi --no-configuration-cache --max-workers=2
```

`--no-configuration-cache` is still required: Paparazzi's resource-preparation task cannot be
stored in the configuration cache. Existing goldens must pass **unchanged** — this migration moves
build wiring and changes no rendering behaviour. A `ClassNotFoundException` naming your module's `R`
class means the convention was not applied.
