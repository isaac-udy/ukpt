# udytils dialogs in the Compose HTML client

udytils' `ConfirmationDestination` and `ErrorDialogDestination` now have Compose HTML destinations,
in udytils `:ui-html`. The Compose HTML client depends on it, and `UkptHtmlTheme` gives the dialogs
the `ukpt-design.css` classes.

These arrive with the change:

- The `embedded-udytils` bump, the `ui-html` substitution in `settings.gradle.kts`, and the
  `udytils-uiHtml` catalog entry.
- `UkptHtmlTheme` in `:platform:client:design-html`, and `.ukpt-button-destructive` in
  `ukpt-design.css`.

`ClientUi.htmlSourceUsesNoComposeUi` now allows `dev.isaacudy.udytils.ui.html` imports. No rule ID
was renamed or removed.

Skip this migration if the project deleted `app/client/web-html`.

## Detection

```bash
test -d app/client/web-html && ! grep -q 'udytils.uiHtml' app/client/web-html/build.gradle.kts && echo "needs migration"
```

## Migration

1. In `settings.gradle.kts`, substitute `dev.isaacudy.udytils:ui-html` with the `:ui-html` project
   of `embedded-udytils`, beside the `ui` substitution.
2. In `app/client/web-html/build.gradle.kts`, add `implementation(projects.platform.client.designHtml)`
   and `implementation(libs.udytils.uiHtml)` to `jsMain`.
3. In `app/client/web-html/…/Main.kt`, wrap the content inside `EnroHtmlContent { }` in
   `UkptHtmlTheme { }`.
4. If a key or `PresentableException` the HTML client shows is built from a `StringResource`,
   provide its text through `LocalHtmlStringResolver` beside `UkptHtmlTheme` (`ukpt-html-web`,
   "udytils dialogs").
5. If the project restyled `ukpt-design.css`, check the `.ukpt-button-destructive` rule against its
   palette.

## Verification

```bash
./gradlew verifyArchitecture
./gradlew :app:client:web-html:check
```

Then open a screen that shows a udytils confirmation or error dialog in the served app, and check
the browser console.
