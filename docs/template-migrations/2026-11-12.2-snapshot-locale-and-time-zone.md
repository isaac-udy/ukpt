# Snapshot tests run in a fixed locale and time zone

`ukpt.snapshot-testing-base` sets the locale and the time zone of the snapshot test JVM. Before
this change the snapshot test JVM used the locale and time zone of the machine, so a golden that
renders a date, a weekday order or a time failed `verifyPaparazzi` on a machine in another locale
or time zone. Material's `DatePicker` is one such component.

Two Gradle properties select the values:

| Property | Format | Default |
| --- | --- | --- |
| `ukpt.snapshotLocale` | `language-COUNTRY`, for example `en-NZ` | `en-US` |
| `ukpt.snapshotTimeZone` | a time zone ID, for example `Pacific/Auckland` | `UTC` |

The build fails at configuration time when either property has an invalid value.

## Detection

After the file sync, verify every golden:

```bash
./gradlew snapshotTest --no-configuration-cache
```

A project is affected when a golden fails. A project is also affected when the project edited
`build-logic/src/main/kotlin/ukpt.snapshot-testing-base.gradle.kts` to set `user.language`,
`user.country` or `user.timezone`:

```bash
grep -n "user\.\(language\|country\|timezone\)" build-logic/src/main/kotlin/*.gradle.kts
```

## Migration

1. Remove the project's own `user.language`, `user.country` and `user.timezone` settings from
   `ukpt.snapshot-testing-base.gradle.kts`, so that the file matches the template.
2. Choose one of two options for the failing goldens:
   - Keep the goldens. Set the locale and time zone the goldens were recorded in, in the
     project's `gradle.properties`:

     ```properties
     ukpt.snapshotLocale=en-NZ
     ukpt.snapshotTimeZone=Pacific/Auckland
     ```

   - Re-record the goldens under the defaults, in each module with a failing golden:

     ```bash
     ./gradlew :feature:<name>:client:recordPaparazzi --no-configuration-cache
     ```

     Open each changed golden image before committing the image.

## Verification

`./gradlew snapshotTest --no-configuration-cache` passes on the developer machine and in CI.
