# Subcutaneous Tests check the server through Server Inspections

A Subcutaneous Test can check what the server stored, besides what the page shows. Before this
change a test could read the server only through a Scenario, which is setup by name and by rule.

- `inspectServer { }` on the test scope runs a block until the block passes or 10 s of real time
  pass, and returns the block's result.
- New Testing construct `ServerInspection`: a function with a `ServerInspection` receiver in a
  `:tests` module's `src/main`. A function with this receiver is no longer a Fixture.
- `ServerInspection.server<T>()` and `ServerInspection.database { }`, a read-only transaction on
  the test's database.
- `Recording<T>`: a Fake records its calls; an Inspection reads them with `calls`,
  `assertSingle { … }` and `assertNone { … }`.
- New rules: `Testing.ServerInspection.placement`, `Testing.ServerInspection.readsOnly`. The
  `readsOnly` rule treats only a `fun interface` in a domain package as a domain interface.
- `awaitAsserted` takes a suspending assertion. Existing calls compile unchanged.

## Detection

```bash
grep -rn "ServerInspection" --include='*.kt' feature
```

A project is affected only if a `:tests` module already declares a function with a receiver
named `ServerInspection`.

## Migration

1. Rename a project function whose receiver is named `ServerInspection` and is not the harness
   type, or move the function to the `:tests` module's `src/main`.
2. Optional: replace a Scenario that a test uses only to check server state with a Server
   Inspection called inside `inspectServer { }`. The `ukpt-testing` skill, "Inspections", shows
   the shape.

## Verification

```bash
./gradlew verifyArchitecture
./gradlew subcutaneousJvmTest
```
