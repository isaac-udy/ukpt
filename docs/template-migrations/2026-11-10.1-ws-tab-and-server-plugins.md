# Server plugins from the graph, and websockets in the Subcutaneous tab

`:platform:server:web` has `ServerPlugin`, a `fun interface` whose `Application.install()`
installs Ktor plugins: authentication, call logging, forwarded headers. `installServerHost` installs
every bound `ServerPlugin` after Koin and before the web platform, so the Subcutaneous harness and
`inProcessServer`, which call `installServerHost` with the graph, install the same plugins as
production. Koin returns the bindings in no defined order; plugins whose order matters are
installed by one binding.

`installServerHost(modules)` no longer takes a `ContentSecurityPolicy`. It serves the policy bound
in the graph, or the platform's default when none is bound, so End To End Tests run under the
production policy.

`installWebPlatform` installs Ktor `WebSockets`, as it installs server-sent events, unless a
`ServerPlugin` installed it first with its own configuration. udytils still does not bundle the
htmx `ws` extension; a page that uses it loads a vendored copy from the project's `static/`.

The Subcutaneous tab follows `ws-connect`. It opens a websocket with the tab's cookies for each
`ws-connect` element under `hx-ext="ws"`, and swaps each text frame as the `ws` extension does:
every top-level element out of band, by its id unless `hx-swap-oob` names a style or a target. A
stream or socket opens when its element enters the page and closes when the element leaves it; this
now holds for `sse-connect` too, which used to open only on a full page load. A `ws-connect` or
`sse-connect` without its extension enabled stays closed, and a robot's failure message says so.
`ws-send` fails the step that reaches it.

New Construct: `ServerWeb.Plugin`, an `internal class [Name]Plugin` implementing `ServerPlugin` in
`server.web`, bound with `singleOf(::[Name]Plugin) bind ServerPlugin::class`. New rules:
`ServerWeb.Plugin.internalVisibility`, `.implementsServerPlugin`, `.noPersistenceInjection`.
`Testing.AdapterTest.placement` now also allows `:platform:common:subcutaneous`'s `src/test`. No
rule ID is renamed or removed.

The platform modules, the harness and the rules arrive with the file sync. Plugin installs in
`Server.kt` and their bindings are project code.

## Detection

```bash
# Ktor plugins installed outside the graph
grep -rn 'install(' --include='*.kt' app | grep -v '/build/' | grep -v 'install(Koin'

# A host that installs Koin and the web platform itself instead of calling installServerHost
grep -rn 'install(Koin)\|install(KoinIsolated)\|installWebPlatform(' --include='*.kt' app | grep -v '/build/'

# A content security policy passed to installServerHost or installWebPlatform
grep -rn 'ContentSecurityPolicy(' --include='*.kt' app | grep -v '/build/'

# Pages that use the ws extension
grep -rn '"ws-connect"\|"ws-send"' --include='*.kt' feature | grep -v '/build/'
```

## Migration

1. Move each `install(Authentication) { … }` into a `ServerPlugin`. Authentication a feature owns
   becomes an `internal class [Name]Plugin` in that feature's `server.web`, taking the domain
   interfaces its `validate` calls (a `JWTVerifier`, a session check) as constructor parameters,
   and bound in the feature's dependency module:

   ```kotlin
   singleOf(::SessionPlugin) bind ServerPlugin::class
   ```

   A value read from configuration, such as a JWT secret, becomes a typed `[Name]Config` bound in
   the module the shell assembles, and the plugin takes it as a parameter.
2. Delete `install(WebSockets)` from `Server.kt`: the web platform installs it. A project that
   configures it (`pingPeriodMillis`, `timeoutMillis`, `maxFrameSize`) installs it from a
   `ServerPlugin` instead, which the platform then keeps.
3. Move each other plugin `Server.kt` installs after Koin (`CallLogging`, `XForwardedHeaders`,
   `DefaultHeaders`, metrics) into a `ServerPlugin` bound in a module of `serverDependencies`.
   Plugins whose order matters go in one binding, in that order. A plugin that must exist for every
   test too, such as authentication, belongs in a feature's dependency module, which the feature's
   test graph lists.
4. Replace a hand-rolled `install(Koin) { … }` and `installWebPlatform(getKoin().getAll(), …)` in
   `Server.kt` with `installServerHost(serverDependencies(…))`. A `WebRoutes` constructed in
   `Server.kt` becomes a binding.
5. Bind the project's `ContentSecurityPolicy` in a module of `serverDependencies`, as a value:
   `single { ContentSecurityPolicy(connectSources = …, reportOnly = …) }`, and drop it from the
   `installServerHost` call.
6. For a page under `hx-ext="ws"`, write its Subcutaneous Tests as for an `sse-connect` page: the
   robot's `see…` waits for what the frames bring. A page that sends with `ws-send` needs an End To
   End Test.

## Verification

```bash
./gradlew :app:server:wiringTest
./gradlew subcutaneousTest
./gradlew :app:server:endToEndTest
./gradlew :platform:common:architecture:verifyArchitecture
```

`Server.kt` installs no plugin outside `installServerHost`. A Subcutaneous Test of a page behind
authentication reaches the page after signing in, and a `ws-connect` page shows the content its
first frame brings.
