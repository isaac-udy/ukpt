# Shared agent guidance and skills

UKPT now uses `AGENTS.md` for project-owned coding-agent guidance and `.agents/skills/` as the
canonical skill location. Codex discovers both directly. `CLAUDE.md` imports `AGENTS.md` and
`UKPT.md`, while `.claude/skills/` links to the canonical skill directories so Claude Code receives
the same instructions without maintaining duplicate copies.

## Detection

A project needs this migration if it keeps project-specific instructions only in `CLAUDE.md`, or
owns real skill directories under `.claude/skills/` without matching skills under
`.agents/skills/`.

## Migration

1. Create a project-owned `AGENTS.md`. Move shared project-specific instructions out of
   `CLAUDE.md`, and tell agents to read the template-owned `UKPT.md` before changing the project.
   Leave genuinely Claude-only instructions in `CLAUDE.md` if the project has any.
2. Ensure `CLAUDE.md` imports both `@AGENTS.md` and `@UKPT.md`.
3. Move each UKPT skill directory from `.claude/skills/` to `.agents/skills/`. Recreate each old
   `.claude/skills/<name>` path as a relative link to `../../.agents/skills/<name>`.
4. Update documentation and scripts to invoke bundled resources through `.agents/skills/`.
5. Keep `AGENTS.md` and `CLAUDE.md` project-owned during later template updates. Sync the canonical
   `.agents/skills/ukpt-*` directories, the `.claude/skills/ukpt-*` compatibility links, and
   `.claude/settings.json` from the template.

## Verification

Confirm every compatibility path is a link and resolves to a skill with valid frontmatter:

```bash
for skill in .agents/skills/ukpt-*; do test -f "$skill/SKILL.md" || exit 1; done
for skill in .claude/skills/ukpt-*; do test -L "$skill" && test -f "$skill/SKILL.md" || exit 1; done
```

Start a fresh Codex and Claude Code session from the repository root and confirm both list the five
UKPT skills. Ask each agent to summarise its project guidance; both should use the project-specific
`AGENTS.md` content and the template-owned `UKPT.md` constraints.
