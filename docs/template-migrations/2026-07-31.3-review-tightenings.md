# Enforcement tightenings from the adversarial review of the side-first catalog

Rules whose enforcement tightened after `2026-07-31.2`, in the same release. Each closes a way
conforming-looking code could evade the stated discipline; none renames an id, so exemptions keep
matching — but code that only passed through the old looseness now fails.

- **`ProjectRules.serialNameEncodesEnclosingType`**: a nested sealed variant's `@SerialName` must
  end with its full type-nesting chain from the outermost declaring type, not just
  `<SealedParent>.<Name>` — two destinations each nesting `Action.Delete` no longer share a
  discriminator. A pre-move fully-qualified pin still passes (the chain is the end of an FQN).
- **`ServerData.tableAccessOwnedByStorage`**: a generated `Table` object may be named only from the
  flat `server.data.storage` package — a Repository querying a table directly now reports. `Row`
  imports stay layer-wide. Imports and fully-qualified body references count equally.
- **`ServerServices.ServiceImpl`**: requires a `:server` module (an impl declared in `:api` now
  fails membership), and the new `implementsItsContract` rule requires `[Name]ServiceImpl` to
  implement its own feature's `@Urpc` `[Name]Service`.
- **`ClientDomain.WorkflowStep` / `ServerDomain.WorkflowStep`**: a step's parent must resolve to a
  `[Name]Workflow`'s nested `Step` contract, and only an `Impl` in the side's `domain` layer is
  exempt from `composedNotInjected` — a ServiceImpl holding a step now reports.
- **`FeatureRules.DependencyModule` (and `DependencyModuleHelper`)**: must sit at exactly the
  feature-root package of a `:client`/`:server` module — a `Dependencies` property in a deeper or
  undeclared package, or in `:api`, no longer classifies.
- Reference matching across the injection/implementation rules is resolved through each file's
  imports (aliases and qualified names included) and compared by fully-qualified name, so an
  import alias no longer evades a rule and a vendor type sharing a project type's simple name no
  longer trips one.

## Detection

Run `./gradlew :platform:common:architecture:verifyArchitecture` after the catalog sync: each
tightening reports under its rule id with the offending declaration.

## Migration

Work each finding as stated by its rule: re-pin a shared-discriminator serial name to the full
nesting chain (a wire-compatibility event — coordinate like any discriminator change); move direct
table queries into the owning StorageClass and state what the caller needed on it; give a
contract-less ServiceImpl its `@Urpc` interface (or rename/delete it) and move any `:api`-declared
impl to `:server`; move workflow-step injection into the composing domain-layer UseCase; move a
misplaced `Dependencies` module to the feature root of its side module.

## Verification

`verifyArchitecture` and `./gradlew validateTemplate` are green.
