# Layouts are a construct, and the platform renders the document

`:platform:server:web` now has two functions where it had one:

- `ukptDocument(state: DocumentState, content: BODY.() -> Unit)` renders `<head>` and `<body>`:
  the htmx configuration, the platform's and the page's stylesheets and scripts, and the error
  region. `DocumentState` gains `stylesheets`, which `ukptLayout` never had.
- `ukptLayout(state: LayoutState, content: MAIN.() -> Unit)` is the default page layout, the
  page's content in `main.page`. It takes a `LayoutState(title, scripts)` in place of the `title`
  and `scripts` parameters.

The rule catalog gains the `ServerWeb.Layout` construct: a top-level `fun HTML.[name]Layout`
that several Pages render inside, such as an app shell with navigation. Its rules:

- `ServerWeb.Layout.takesItsViewStateAndContent`: a Layout takes a `[Name]State` and a content
  lambda, nothing else.
- `ServerWeb.Layout.rendersThroughThePlatform`: a Layout calls another Layout or `ukptDocument`.

A new group rule, `ServerWeb.documentFromThePlatform`, reports a `server.web` file that imports
`kotlinx.html.head` or `kotlinx.html.body`. `ServerWeb.Page.rendersThroughLayout` keeps its ID;
a Page may now render through any Layout. No rule ID is renamed or removed.

## Detection

```bash
grep -rn "ukptLayout(" --include=*.kt . | grep -v -e '/build/' -e '^./embedded-' | grep -v "LayoutState("
grep -rln "import kotlinx.html.head$\|import kotlinx.html.body$" --include=*.kt feature
```

The first finds calls to the old `ukptLayout` signature, where `ukpt` is the project's
identifier prefix. The second finds feature files that render their own document.

## Migration

1. Sync `platform/server/web` (`UkptDocument.kt`, `UkptLayout.kt`, `WebPlatform.kt`) and the rule
   catalog (`rules/serverweb/`) as template-owned files (see `ukpt-template-update` §5).
2. Rewrite each `ukptLayout(title = …, scripts = …) { … }` call as
   `ukptLayout(LayoutState(title = …, scripts = …)) { … }`.
3. For a feature function that renders its own `head { }` or `body { }`, usually a shell with
   navigation that several pages share:
   - Name it `[name]Layout`.
   - Gather its parameters into a `[Name]LayoutState` data class.
   - Render through `ukptDocument(DocumentState(…)) { … }`, moving its stylesheets into
     `DocumentState.stylesheets` and its script files into `DocumentState.scripts`.
   - Each Page passes its own `[Name]LayoutState`, usually carried on its View State.
