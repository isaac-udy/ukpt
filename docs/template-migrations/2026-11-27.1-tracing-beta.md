# Tracing, analytics and metrics from spans (beta)

The udytils trace compiler plugin records a span for each call and construction in the `feature`
packages. Rules in `:app:client:telemetry` derive analytics events and metrics from the spans, and
the urpc client and server host carry the trace from the client to the server. The rule API and the
telemetry module structure are a beta: a later template version marks them ready for production
and adds a migration entry for the changes made until then.

The migration has two parts:

- **Part 1, the build wiring.** Every project applies Part 1, because `:platform:client:network` and
  `:platform:server:host` depend on `trace-runtime` after the file sync. Part 1 adds no span sink,
  so the app records nothing.
- **Part 2, the telemetry modules (beta).** A project that is not ready to adopt a beta API skips
  Part 2. Its features stay untraced.

## Detection

```bash
grep -n 'trace-runtime' settings.gradle.kts
grep -n 'app:client:telemetry' settings.gradle.kts
```

A project is affected by Part 1 if the first command prints nothing, and by Part 2 if the second
command prints nothing and the project adopts the beta.

## Migration

### Part 1: build wiring

1. In `settings.gradle.kts`, add these lines to the `dependencySubstitution` block of
   `includeBuild("embedded-udytils")`:
   ```kotlin
   substitute(module("dev.isaacudy.udytils:trace-runtime")).using(project(":trace-runtime"))
   substitute(module("dev.isaacudy.udytils:trace-otlp")).using(project(":trace-otlp"))
   substitute(module("dev.isaacudy.udytils:trace-enro")).using(project(":trace-enro"))
   substitute(module("dev.isaacudy.udytils:trace-compiler-plugin")).using(project(":trace-compiler-plugin"))
   substitute(module("dev.isaacudy.udytils:trace-gradle-plugin")).using(project(":trace-gradle-plugin"))
   ```
2. In `gradle/libs.versions.toml`, add under `[libraries]`:
   ```toml
   udytils-traceGradlePlugin = { module = "dev.isaacudy.udytils:trace-gradle-plugin" }
   udytils-traceRuntime = { module = "dev.isaacudy.udytils:trace-runtime" }
   udytils-traceOtlp = { module = "dev.isaacudy.udytils:trace-otlp" }
   udytils-traceEnro = { module = "dev.isaacudy.udytils:trace-enro" }
   ```
3. In the root `build.gradle.kts`, add `classpath(libs.udytils.traceGradlePlugin)` to the
   `buildscript { dependencies { } }` block, and add
   `apply(plugin = "dev.isaacudy.udytils.trace-viewer")` after the `dev.isaacudy.udytils.atlas`
   line. The viewer adds `traceViewerStart`, `traceViewerStop` and `traceViewerOpen`.
4. `:platform:client:network` and `:platform:server:host` take their changes from the file sync:
   `TraceparentInterceptor` and the `callContext` of `installServerHost`.

### Part 2: telemetry modules (beta)

1. Copy `app/client/telemetry/` and `app/client/telemetry/tests/` from the template, and add
   `include(":app:client:telemetry")` and `include(":app:client:telemetry:tests")` to
   `settings.gradle.kts`. Replace the template's `:feature:core` rules, events and metrics with the
   project's own.
2. In each feature's `client` and `server` build file, apply the trace plugin to the `feature`
   packages, as `feature/core/client/build.gradle.kts` does. Setting `ukpt.trace=false` turns the
   plugin off for a build.
3. In `app/client/telemetry/build.gradle.kts`, add a `traceSites(...)` dependency for each feature
   client module.
4. Add `telemetryDependencies` to the module lists in both `ClientDependencies.kt` files, register
   `plugin(TraceNavigationPlugin())` in the Enro navigation of each client shell, and add the
   `udytils.traceEnro` and `projects.app.client.telemetry` dependencies to `app/client/common` and
   `app/client/web-html`.
5. For trace export, add `udytils.traceOtlp` and `ktor.clientCio` to `app/client/desktop` and
   `app/server`, and call `exportTraces` from `main()` when `UKPT_TRACE_EXPORT` is set, as the
   template's `Main.kt` and `Server.kt` do.
6. Port the catalog changes: the `Telemetry` rule group (`TraceRules`, `AnalyticsEvent`, `Metric`),
   the `:app:[side]:telemetry:tests` placement in `Testing.SubcutaneousTest.placement`, and the
   test-support module in `ModuleRules.testSupportOnlyFromTests`. No rule ID is renamed or removed.

## Verification

```bash
./gradlew verifyArchitecture :app:client:telemetry:tests:jvmTest
```

Part 1 alone: `./gradlew verifyArchitecture` and the platform compiles pass, and no
`:app:client:telemetry` module exists.
