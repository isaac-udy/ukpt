# `ServerData.noServiceImports` is now `ServerData.noEntryPointImports`

The rule that kept `server.data` from importing `server.services` is now an allow-list: `server.data`
imports no `feature.[name].server.[layer]` package other than `server.domain` and `server.data`. It
covers `server.services` as before, and any other server entry-point layer a project adds.

The rule ID changed from `ServerData.noServiceImports` to `ServerData.noEntryPointImports`.

## Detection

```bash
grep -rn "ServerData.noServiceImports" --include=*.kt --include=*.kts --include=*.md . \
  | grep -v -e '/build/' -e '^./embedded-' -e '^./docs/template-migrations/'
```

The project is affected if any `@ArchitectureException(ruleIds = [...])`, build-file
`// architecture-exception:` comment, rule catalog source or skill still cites the old ID.

## Migration

1. Sync the rule catalog change in `rules/serverdata/ServerData.kt` (see `ukpt-template-update` §5).
2. Replace every remaining `ServerData.noServiceImports` with `ServerData.noEntryPointImports`.
3. If `server.data` imports a project-specific server layer that is neither `domain` nor `data`,
   the rule now reports it. Move the shared type into `server.domain`, or into the feature root
   when both sides of the wire need it.

## Verification

```bash
./gradlew :platform:common:architecture:updateArchitectureDocumentation
./gradlew :platform:common:architecture:verifyArchitecture
./gradlew validateTemplate
```
