# Subcutaneous tests and page robots

Subcutaneous Tests now run. The harness `:platform:common:subcutaneous` starts a feature's
production server graph in-process on Ktor's test engine, against an embedded Postgres cloned from
a migrated template for every test, and opens a tab on it: `asUser(path) { … }`. The tab sends the
requests htmx sends, swaps the responses into `hx-target` as `hx-swap` says, applies out-of-band
swaps, follows `sse-connect` streams, and runs no JavaScript; `asUser(path, scripts = false)`
checks that a page works without it.

Tests drive pages through robots, one per page. `:platform:common:robots` holds `PageRobot`,
`Locator`, `User` and `PageDriver`; a feature's robots, its test graph and its scenarios live in a
new `:feature:<name>:tests` module (convention `ukpt.feature-tests`), and its Subcutaneous Tests in
that module's `src/test`. `:feature:core:tests` is the worked example (`GreetingsPageRobot`,
`GreetingsPageTest`), and replaces `UkptRoutesTest`. The feature's `[Name]Paths` and `[Name]Ids`
objects are public, for the robots.

Every Page now fails `ServerWeb.Page.hasARobot` until a `[Name]PageRobot` exists, and every robot
fails `Testing.Robot.usedBySubcutaneousTests` until a Subcutaneous Test calls its entry point.

The harness, the robots module, the convention, the catalog entries (the Kover plugin), the root
`subcutaneousCoverage` task and the rules arrive with the file sync. The `:tests` modules and their
tests are project code.

New rules: `Testing.SubcutaneousTest.entryPointVocabularyOnly`, `.runsInTheHarness`,
`.noInfrastructureImports`; `Testing.Robot.placement`, `.onePageEntryPoint`, `.userActionNames`,
`.usedBySubcutaneousTests`; `Testing.Scenario.seedsThroughServerDomain`;
`Testing.TestGraph.onePerTestsModule`, `.productionModulesOnly`; `Testing.Fake.subcutaneousEdgesOnly`;
`ServerWeb.Page.hasARobot`; `ModuleRules.testsModuleShape`. New guidance:
`Testing.Scenario.returnsHandles`. New Constructs: `Testing.Scenario`, `Testing.TestGraph`,
`Testing.Robot`. No rule ID is renamed or removed.

`PgNotificationBus` (embedded-udytils) gains `awaitListening(channel)`. The bus runs `LISTEN` for a
new channel on its next poll cycle, so a flow that reads current state and then follows
notifications lost a change made in that window.

## Detection

```bash
# Pages, each needing a robot
grep -rn 'fun HTML\.[a-z][A-Za-z]*Page(' --include='*.kt' feature | grep -v '/build/'

# Route tests to move into a :tests module
grep -rl 'testApplication' --include='*Test.kt' feature | grep -v '/build/'

# Features without a :tests module
for d in feature/*/; do [ -d "$d/server" ] && [ ! -d "$d/tests" ] && echo "$d"; done

# Storage flows that read current state and then follow the notification bus
grep -rn 'listen(' --include='*.kt' feature | grep -v '/build/'
```

## Migration

1. Sync `embedded-udytils` to the template's commit (`git submodule update --init --recursive`).
2. Make each feature's `[Name]Paths` and `[Name]Ids` objects public.
3. For each feature with a `:server`, add `:feature:<name>:tests` from the `ukpt-feature-slice`
   skill's templates.md: the build file, `include(":feature:<name>:tests")` in
   `settings.gradle.kts`, `<name>TestGraph` listing the feature's `<name>ServerDependencies`
   through `featureServer(…)`, and a scenarios file for the data the tests need, written through the
   server domain interfaces.
4. For each Page, add `<Name>PageRobot.kt` to the `:tests` module's `src/main`, copying
   `GreetingsPageRobot.kt`: the `User.on<Name>Page` entry point listing the paths the page renders
   at, and one `click…`/`enter…`/`see…` function per step, locating elements from the feature's Ids.
5. Write the page's `@SubcutaneousTest`s in the module's `src/test`, copying `GreetingsPageTest.kt`:
   seed in `given { }`, open the page with `asUser(<Name>Paths.…) { on<Name>Page { … } }`. Add one
   `scripts = false` test per form that must work without JavaScript.
6. Delete each route test (`testApplication` + jsoup) the new tests replace. A test that renders a
   page, component or event stream with fixed state stays in `:server` as a `@ComponentTest`.
7. In each storage `observe()` built on `PgNotificationBus.listen(channel)` with an initial read,
   call `notificationBus.awaitListening(channel)` first, as `GreetingStorage.observe` does.
8. Run `verifyArchitecture` and fix each failure as the `ukpt-testing` skill describes. A page using
   an htmx attribute the tab does not implement (`hx-include`, `hx-select`, `hx-select-oob`,
   `hx-params`, `hx-encoding`, `hx-prompt`) fails the step that reaches it; cover that page with an
   End To End Test.

## Verification

```bash
./gradlew subcutaneousTest
./gradlew :platform:common:architecture:verifyArchitecture
./gradlew subcutaneousCoverage
```

`subcutaneousTest` runs each `:tests` module's tests. `verifyArchitecture` reports no
`ServerWeb.Page.hasARobot` or `Testing.Robot.usedBySubcutaneousTests` failures.
`build/reports/kover/html/index.html` lists the feature `:server` classes.
