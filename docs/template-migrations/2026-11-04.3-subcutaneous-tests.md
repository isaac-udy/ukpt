# Subcutaneous tests

Subcutaneous Tests now run. The harness `:platform:common:subcutaneous` opens a ViewModel from a
feature's production client graph, with the feature's server graph running in-process on Ktor's
test engine against an embedded Postgres cloned from a migrated template for every test. A
feature's Subcutaneous Tests, its test graph and its scenarios live in a new
`:feature:<name>:tests` module (convention `ukpt.feature-tests`). `:feature:core:tests` is the worked
example, and replaces the ViewModel unit test in `:feature:core:client`'s `commonTest`.

Every ViewModel now fails `ClientUi.ViewModel.subcutaneouslyTested` until a Subcutaneous Test
references it, and `ClientUi.ViewModel.publicFunctionsExercised` until each of its public
functions is called in one.

The harness, the convention, the catalog entries (`udytils-viewmodel`, the Kover plugin), the root
`subcutaneousCoverage` task and the rules arrive with the file sync. The `:tests` modules and their
tests are project code.

New rules: `Testing.SubcutaneousTest.entryPointVocabularyOnly`, `.viewModelsFromTheGraph`,
`.runsInTheHarness`, `.noInfrastructureImports`; `Testing.Scenario.seedsThroughServerDomain`;
`Testing.TestGraph.onePerTestsModule`, `.productionModulesOnly`; `Testing.Fake.subcutaneousEdgesOnly`;
`ClientUi.ViewModel.subcutaneouslyTested`, `.publicFunctionsExercised`; `ModuleRules.testsModuleShape`.
New guidance: `Testing.Scenario.returnsHandles`. New Constructs: `Testing.Scenario` (a function with
a `Scenario` receiver) and `Testing.TestGraph` (a top-level `SubcutaneousGraph`); `Testing.Fixture`
no longer matches either. No rule ID is renamed or removed.

`PgNotificationBus` (embedded-udytils) gains `awaitListening(channel)`. The bus runs `LISTEN` for a
new channel on its next poll cycle, so a flow that reads current state and then follows
notifications lost a change made in that window. `:feature:core`'s `GreetingStorage.observe` now
awaits it before the initial read.

## Detection

```bash
# ViewModels, each needing a Subcutaneous Test
grep -rl ': ViewModel()' --include='*ViewModel.kt' feature | grep '/src/commonMain/' | grep -v '/build/'

# ViewModel unit tests to move into a :tests module
grep -rl '@UnitTest' --include='*ViewModelTest.kt' feature | grep -v '/build/'

# Features without a :tests module
for d in feature/*/; do [ -d "$d/client" ] && [ ! -d "$d/tests" ] && echo "$d"; done

# Storage flows that read current state and then follow the notification bus
grep -rn 'listen(' --include='*.kt' feature | grep -v '/build/'
```

## Migration

1. Sync `embedded-udytils` to the template's commit (`git submodule update --init --recursive`).
2. For each feature with a `:client`, add `:feature:<name>:tests` from the `ukpt-feature-slice`
   skill's templates.md §7: the build file, `include(":feature:<name>:tests")` in
   `settings.gradle.kts`, `<name>TestGraph` listing the feature's `<name>ClientDependencies` and
   `<name>ServerDependencies` through `featureClient(…)`/`featureServer(…)`, and a scenarios file
   for the data the tests need, written through the server domain interfaces.
3. Write a `@SubcutaneousTest` per ViewModel in the module's `src/test`, copying
   `feature/core/tests/src/test/kotlin/feature/ukpt/tests/UkptViewModelTest.kt`. Call every public
   ViewModel function in at least one test. Replace a dialog's result with
   `screen.navigation.assertOpened<…>().sendCompletedForTest()`; seed data in `given { }`.
4. Delete each ViewModel `@UnitTest` the new tests replace. Remove `libs.enro.test` from a
   `:client` module's `commonTest` when nothing there uses it.
5. A server behaviour no screen reaches gets a server-entry test with `service<<Name>Service>()`
   (`GreetingServiceTest.kt`).
6. In each storage `observe()` built on `PgNotificationBus.listen(channel)` with an initial read,
   call `notificationBus.awaitListening(channel)` first, as `GreetingStorage.observe` does:
   ```kotlin
   fun observe(): Flow<List<Row>> = flow {
       notificationBus.awaitListening(CHANNEL)
       emitAll(notificationBus.listen(CHANNEL).onSubscription { emit(INITIAL_READ) })
   }.conflate().map { list() }.distinctUntilChanged()
   ```
7. Run `verifyArchitecture` and fix each failure as the `ukpt-testing` skill describes. A fake in a
   `:tests` module may replace only an IntegrationClient's interface, the clock, or a `platform`
   interface; bind it with `subcutaneous(graph, edges = { server { … } })`.

## Verification

```bash
./gradlew subcutaneousTest
./gradlew unitTest
./gradlew :platform:common:architecture:verifyArchitecture
./gradlew subcutaneousCoverage
```

`subcutaneousTest` runs each `:tests` module's tests and `unitTest` runs none of them.
`verifyArchitecture` reports no `ClientUi.ViewModel.subcutaneouslyTested` or
`publicFunctionsExercised` failures. `build/reports/kover/html/index.html` lists the feature
`:client` and `:server` classes.
