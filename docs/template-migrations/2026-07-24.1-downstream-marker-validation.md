# `validateTemplate` now checks the full downstream marker schema

`TemplateRepositoryValidator` previously validated only `templateVersion` in `.ukpt/template.json`.
For a **downstream** marker (one carrying a `project` rename map) it now also validates the rest of
the schema the `ukpt-template-update` skill depends on:

- `templateCommit` — present, a string, a 40-character git SHA.
- `project` — an object with non-blank `package`, `name`, and `typePrefix`.
- `submodules` — an object with 40-character SHAs for `embedded-enro` and `embedded-udytils`.

A marker missing or malforming any of these used to pass silently and then misdirect the next update
(a missing `templateCommit` falls back to a fuzzy `git log -S`; a missing or wrong rename map is
worse). The template's own marker has only `templateVersion` and is exempt — these checks apply only
to markers with a `project` map.

## Detection

Run `./gradlew validateTemplate`. A downstream project whose marker predates the full schema, or was
hand-edited, now fails with a `.ukpt/template.json` message naming each missing or malformed field.

## Migration

Complete `.ukpt/template.json` to match the schema in the `ukpt-new-project` skill:

```json
{
  "templateVersion": "…",
  "templateCommit": "<40-hex SHA of the template commit this project last synced from>",
  "project": { "package": "<pkg>", "name": "<project-name>", "typePrefix": "<ProjectName>" },
  "submodules": {
    "embedded-enro": "<40-hex SHA>",
    "embedded-udytils": "<40-hex SHA>"
  }
}
```

Recover `templateCommit` with `git log -S '<templateVersion>' -- .ukpt/template.json` in a template
clone; take the submodule SHAs from the project's checked-out gitlinks (`git ls-tree HEAD embedded-enro`).

## Verification

`./gradlew validateTemplate` passes.
