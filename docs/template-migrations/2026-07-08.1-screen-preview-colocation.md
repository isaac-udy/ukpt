# Screen previews must be co-located with their ScreenContent

`UiLayer.Composable.screenContentPreview` was tightened. The `@Preview` composable that renders a
`[Name]ScreenContent` must now live in the **same file** as that ScreenContent, not merely somewhere
in the same module. The rule ID is unchanged.

Since `UiLayer.Screen.screenContentCompanion` already requires `[Name]ScreenContent` to sit in the
same file as its Screen, this keeps each screen's preview next to the screen it renders — discoverable
and maintained alongside it — instead of drifting into a single shared "screen previews" file that
accumulates every feature's previews.

## Detection

The project is affected if a `[Name]ScreenContent`'s `@Preview` lives in a different file from the
ScreenContent — most commonly a shared previews file (e.g. `ScreenPreviews.kt`) that gathers previews
for many screens. Those ScreenContents now fail `UiLayer.Composable.screenContentPreview` with
"no @Preview composable in the same file calls `…ScreenContent(`". Previews for non-Screen
composables are unaffected — they may live anywhere.

## Migration

1. For each failing `[Name]ScreenContent`, move its `@Preview` function into the same file as the
   ScreenContent (the same file as the Screen). Delete the now-empty shared previews file once every
   preview has been relocated.
2. Re-record the Paparazzi goldens for affected client modules — a preview's golden image name is
   derived from its containing file, so moving it renames the golden:

   ```
   ./gradlew :feature:<name>:client:recordPaparazzi
   ./gradlew :feature:<name>:client:verifyPaparazzi
   ```

   Delete any orphaned golden images left behind under `src/androidHostTest/snapshots/images/`.

Rule IDs are unchanged, so existing `@ArchitectureException(ruleIds = ["…screenContentPreview"])`
opt-outs keep working.

## Verification

```
./gradlew :platform:common:architecture:verifyArchitecture
```

Must be green, with each `[Name]ScreenContent` previewed by a `@Preview` in its own file.
