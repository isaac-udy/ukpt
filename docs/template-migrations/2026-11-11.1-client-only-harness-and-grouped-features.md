# Client-only Subcutaneous harness, grouped features, Android adapter tests

The Subcutaneous harness is split in two:

- `:platform:common:subcutaneous` builds the client graph, opens ViewModels and applies edges. It
  has no server or Postgres dependency.
- `:platform:common:subcutaneous-server` holds `featureClient`, `featureServer` and
  `inProcessServer`, and runs the server in-process over embedded Postgres.

`SubcutaneousGraph.server` is now a `SubcutaneousServer`, which `featureServer(…)` returns. It is
optional: a project whose backend it does not own writes `SubcutaneousGraph(client = …)` and fakes
the backend at the client edge. `Scenario`, `Edges` and `Teardown` have public constructors so the
two modules can share them.

The rule catalog supports grouped features. A feature may nest under a group directory
(`:feature:capture:insta`): its name spans the group, its packages nest with it
(`feature.capture.insta.client.ui`), and its `:tests` module is test source.

`Testing.AdapterTest.placement` accepts a client module's `androidHostTest`, for an adapter in
`androidMain`.

No rule ID is added, renamed or removed. `ModuleRules.testSupportOnlyFromTests` lists
`:platform:common:subcutaneous-server`.

## Detection

```bash
# :tests modules and desktop tests that run a server through the harness
grep -rln 'platform.common.subcutaneous\b' --include='build.gradle.kts' feature app

# Catalog files a project customised for grouped features
grep -rln 'featureNameOfPackage' platform/common/architecture/src/main/kotlin
```

## Migration

1. A `:tests` module or `:app:client:desktop` test set whose graph has a `server = featureServer(…)`,
   or that calls `inProcessServer`, replaces `projects.platform.common.subcutaneous` with
   `projects.platform.common.subcutaneousServer`. Add `include(":platform:common:subcutaneous-server")`
   to `settings.gradle.kts`.
2. A project without a server keeps `projects.platform.common.subcutaneous`, deletes
   `:platform:common:subcutaneous-server` and its include, and writes its graphs and backend edges
   as `ukpt-testing`, "Without a server", describes.
3. Apply the catalog changes through the rule sync. A project that already added grouped-feature
   support to its catalog takes the template's version of those files; the two are the same change.
4. Move an `androidMain` adapter's test into the module's `androidHostTest` and annotate it
   `@AdapterTest`.

## Verification

```bash
./gradlew :platform:common:architecture:verifyArchitecture
./gradlew subcutaneousTest
./gradlew snapshotTest --no-configuration-cache
```

`subcutaneousTest` passes for every `:tests` module. `snapshotTest` runs each `androidHostTest`
Adapter Test with the module's snapshots.
